# PR96 reader geometry validation

`tools/pr95_call_budget.py` now reads `MAPFAC_MX`, `MAPFAC_MY`, `XLAT`, and
`XLONG` through `pr87_native_history._finite` before selecting the captured
tile. The reader rejects nonfinite values and declared `_FillValue` or
`missing_value` sentinels across each full history record. It also requires
finite positive `DX`, `DY`, `MAPFAC_MX`, and `MAPFAC_MY` before calculating
tile area. Latitude and longitude retain the existing finite-value check; no
new geographic range policy is applied.

The focused tests use small NetCDF files and cover all four variables against
both declared sentinel attributes, NaN and infinity, valid unchanged area and
coordinates, and nonpositive grid spacing and map factors. They exercise the
actual NetCDF decoding and `_finite` path.

Validation: `pytest -q tests/test_pr95_call_budget.py` (29 passed); `git diff
--check` clean. This check covers reader input validation only. No large C4
capture was run as part of this fix.

The [closed C4 geometry check](evidence/pr96_reader_20261021/c4_geometry.json) reads both receipt-bound T0 histories. For each 64,960-column tile, the strengthened reader returns exactly the former area/latitude/longitude values and rejects no declared sentinel or nonfinite operand. History hashes are checked before and after reading. This does not rerun the full capture reduction or close its water residual.
