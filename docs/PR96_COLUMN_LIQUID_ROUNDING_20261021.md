# PR96 selected-column liquid water closure

The −10.784439 kg residual in the PR95 OFF column (`i=117, j=141`) is accounted for by REAL32 storage rounding in the liquid-cloud vapor transfer at the end of KDM6. The diagnostic replay recorded 22 full-cloud evaporation events and 2 ordinary condensation events. Per event, the reducer evaluates the captured REAL32 operands as exact rational values, computes the exact two-operand sum, selects the nearest REAL32 result with ties to even, and compares that result with the captured post-store bits.

For `i=117, j=141`, the Q stores contribute −10.784439105942 kg and the QC stores contribute 0 kg. Using exact rational values reconstructed from the REAL32 endpoint bits and the captured binary64 layer mass weights, the sum of per-event store errors equals the six-species endpoint change **exactly at all 39 levels**. The ordinary float64 reduction differs from the independent six-species column residual (−10.784439105541 kg) by 4.02e−10 kg. Every observed store matches its independently computed REAL32 RNE result. The largest individual error is 0.943 of the local conservative half-ULP; the summed weighted half-ULP bounds are 57.007 kg for Q and 0.0613 kg for QC. The account does not assign a correction to force the column residual.

In the full-evaporation branch, the source adds the entire REAL32 cloud-water extent to Q and clears QC to zero. QC therefore has no store error in these events, while Q is rounded at its own store. This explains the one-sided error. The two ordinary condensation events are recorded separately and use the actual REAL32 product `pcond*DTCLD` as the approved transfer. Activation instrumentation is also present; it emitted no nonzero transfer for either column.

As an independent nearby replay, `i=116, j=141` has 22 full-evaporation events and 2 ordinary condensation events. Its phase-store errors sum to +1.734944694982 kg; the exact endpoint/event identity also passes at every level. The ordinary float64 reduction differs from the actual six-species column residual (+1.734944694676 kg) by 3.07e−10 kg. All stores match independently rounded REAL32 results, and all 17 post-call state fields match the captured actual C4 post-call state byte for byte (2,652 bytes per column). This confirms the representation-rounding explanation on a second actual column; it does not establish full-tile or global closure.

## Diagnostic scope and provenance

The instrumentation adds trace writes around the existing activation and liquid condensation/evaporation stores. It records raw REAL32 bits for the rates, `DTCLD`, signed transaction extent, and before/after Q/QC values, plus REAL64 exact operand products. It does not change a physical expression, branch, guard, or state update. The diagnostic translation unit retains the two PR95 cold/warm ledger gates. The patch was regenerated with zero context lines to remove trailing-whitespace-only context; applying it to the frozen diagnostic base reproduces the same instrumented-source hash, so this is a patch-format change only. Its source is a diagnostic copy of the preprocessed C4 source, SHA-256 `24e3466d9d2a5dd12485540422b6976490152094e5e947cd0f85ab7508d1f2a7`; the liquid trace delta is preserved in [the source patch](../tools/pr96_column_liquid_trace.patch). It compares the endpoint and event error sums as exact rational values at each level; the stored column residual is not used to derive or fit any event term.
