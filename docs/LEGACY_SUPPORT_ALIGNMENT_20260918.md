# Legacy continuity: 지원영역과 수평 face 계수 정렬

기준은 PR #27의 `5564e8c`이며, [첫 연산자 폐합 기록](LEGACY_OPERATOR_CLOSURE_20260918.md)을 대체하지 않고 후속 원인 분석을 추가한다.
수정 소스 SHA256은 `e5a669b5f6c8ac005ba433c6e21149efb4c75d6eb7d8a5020205305d9b28f2e0`이다.

## 원인과 최소 수정

`active(i,j,k)`는 같은 위치의 influence로 결정된다. 그러나 저장 U face `(i,j,k)`는
pressure 행 `(i,j+1,k+1)`과 `(i+1,j+1,k+1)`을 연결하면서 이전에는
`beta(i,j,k)`와 `beta(i+1,j,k)`를 읽었다. V에도 대응하는 위치 차이가 있었다.
두 활성 행의 influence가 양수여도 다른 위치의 0 때문에 연결 계수가 0이 됐다.

이제 각 수평 face의 mobility는 **그 face가 연결하는 두 행**의
`c=beta/(2*erru)`를 조화평균하여 구성한다. 기존 face gradient/metric,
수직 계수, active mask, RHS `-D(y)`, 고정 경계, solver 및 허용오차는 유지한다.
생산 수정은 `qbal_continuity_setup`의 두 수평 계수 계산에 한정된다.
새 solver 또는 부분 균형 모드를 추가하지 않았다.

| 실제 235×283×22 배열 | `5564e8c` | 수평 위치 정렬 후 |
|---|---:|---:|
| 활성 행 | 723,638 | 723,638 |
| 양의 계수로 연결된 face | 2,042,280 | 2,076,088 |
| 연결성분 | 222 | 8 |
| 영행 | 171 | 4 |
| 부적합 닫힌 성분 | 222 | 8 |

추가된 33,808개 face는 U 17,313개와 V 16,495개이며, 제거된 face는 없다.
기존 누락 face 모두에서 실제 연결 행의 beta는 양수이고, 이전 참조 위치의 beta 중
적어도 하나는 0이었다. 실제 wind donor는 유한하고 sentinel이 아니었다.
활성 행 좌표와 RHS는 전후 비트 단위로 같다. 남은 네 영행은 활성 이웃 자체가 없다.
따라서 167개 영행 제거는 RHS 변경이나 경계 개방의 결과가 아니다.

## 남은 실패는 반복법 문제가 아니라 해 존재 조건이다

닫힌 성분에서 `A^T z=0`이면 어떤 승수에도

```text
r = A lambda - b
z^T r = -z^T b
||r||inf >= |z^T b| / ||z||1
||r||2   >= |z^T b| / ||z||2
```

가 성립한다. 진단 도구는 기존 왼쪽 영공간 인증 뒤 이 하한을 보고한다.
이는 수치적으로 인증한 영벡터에 의존한 값이며 엄밀한 구간연산 증명은 아니다.
실제 사례는 `dx==dy`, `dp=5000 Pa`로, `z`는 성분 안에서 `dx*dp`에 비례한다.
이는 **현재 이산 연산자의 내적 가중치**이며 native 건조질량 또는 물리적 셀 체적이라고
해석하지 않는다. 이 가중합에서 내부 face는 상쇄되고 고정된 경계 유량의 결함이 남는다.

수정 후 가장 큰 722,376행 성분의 정규화 `z^T b`는 `7.089633754173002e-6`이다.
잔차 무한 norm의 인증 기반 하한은 약 `7.09e-6`으로 현재 기준 `1e-10`을 넘는다.
2-norm 하한은 약 `0.00602548`, 초기 RHS 2-norm은 약 `0.0997164`다.
다른 7개 성분도 부적합하다. 따라서 반복수·solver·전처리만 바꿔 전체 상태의
continuity를 0으로 만들 수 없다. 자동 RHS 평균 제거와 허용오차 완화는 적용하지 않았다.

가장 큰 성분의 `abs(diag(A))` 범위는 약 `1.53e-33`–`6.95e-7`, 비율은
`4.55e26`이다. 이는 큰 **계수 대비**이지 조건수 추정값이 아니다. 호환성 해결 이후
대각 스케일링·전처리·gauge 처리를 검토할 근거로 남긴다.

## 검증과 다음 종료 조건

- X/Y 각각 두 활성 행만 둔 회귀는 이전 참조 위치의 beta가 0인 상태를 재현한다.
  이전 소스는 양의 연결 검사에서 실패하고, 수정 소스는 비영 호환 RHS `(-1,+1)`을 푼다.
- Pinned Intel O0/O2 집중 검사, `A=DG`, 가변계수 solve, 동결 face, 원복 및 변이 대조군을 검증했다.
- BALCON와 nonlinear O0/O2 및 기존 실패/원복 대조군을 검증했다.
- 실제 배열의 O0/O2 sparse export는 바이트 일치한다. source/snapshot hash와
  8개 닫힌 성분·4개 영행을 고정한 gate를 사용한다.
- 독립 Python 성분 진단 7개 회귀는 정확한 2행 반례·영행·공통 배율에 대한 하한을 확인한다.
- 같은 90개 입력의 전체 QBAL도 새 Intel O0/O2 빌드로 실행했다. 두 실행 모두
  초기 continuity에서 8개 성분의 부적합을 검출하여 exit 1로 종료했고 balance 파일은 0개다.
  처음 실행의 Intel runtime 경로 누락(exit 127)은 별도 보존하고 올바른 프로필로 재실행했다.
  근거는 `scratch/support_alignment_20260918/support_alignment_receipt.json`이다.

근거는 `scratch/support_alignment_20260918/`의 로그·JSON과
유지 저장소 `scratch/compatibility_cause_20260918/`의 독립 감사다.
실자료 snapshot은 `96932e53e5f30bf3e9c307617765aaa7200750ec01d4ead6b45842faf97fa661`이며,
수정 sparse export는 `dceb0827dc26bd09510568a9ae1bfe6889c1d09a9a809d738559ac37a278b335`다.

후속 작업은 원래 전체 상태 목표를 만족시킬 수 있는 경계/source 조건을 명시하거나,
허가된 증분만의 projection으로 목표를 명확히 재정의하는 것이다. 어느 경우든 각 성분의
해 존재 조건을 먼저 검증해야 한다. 단순히 영행을 제외하거나 작은 beta에 floor를 주어
성공으로 바꾸지 않는다. 비영 ON, native 전달 및 과학적 승인은 계속 보류한다.
