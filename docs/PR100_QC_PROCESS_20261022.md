# PR100 fixed-support QC process account

## Scope

This report records a source-ordered observer replay over the fixed 613-cell QC support. The observer records each direct QC state write with the call, latitude/loop, grid indices, order, and REAL32 before/after values. The reducer verifies each cell's ordered write chain and that the writes telescope exactly to the native PRE/POST QC fields.

The work is observational. It changes no physical process equations and makes no closure or skill claim.

## Source labels and packet limits

Raw source labels remain unchanged. The offline interpretation mapping corrects two misleading names: `GRAUPEL_TO_CLOUD` writes `qrs(i,k,1)` (rain) into QC and clears that rain slot, so its semantic alias is tiny-rain-to-cloud; no event row was captured on this fixed support. `ICE_EXTINCTION` marks a complete-cloud-freezing branch that transfers QC to QI and clears QC; its near-zero QC increment is not an amount of physical ice loss. A `CUTOFF` event count likewise does not imply QC removal; captured before/after QC is unchanged.

The `CONDENSATION` tag is split by observed stored QC delta sign. Negative deltas indicate partial-evaporation direction, positive deltas condensation direction, and zero is only a zero QC store change; the requested E is not captured. Ordinary write packet columns are zero-fill sentinels and mean N/A, not measured zero rates. Cold/warm packet terms are REAL32 diagnostics and are shown separately from the one actual QC state delta. No total-water or process-ledger closure is implied.

## Limits and review

This account covers one first-call replay over the declared support. It does not establish a full-domain water balance, process causality, observation skill, or scientific approval. The bounded public evidence is under [`docs/evidence/pr100_qc_process_20261022/`](evidence/pr100_qc_process_20261022/). The independent source/math review found no equation, coordinate, sign, N/A-field, or vector-attribution blocker; it left build compliance conditional on a fresh-cwd rerun. The subsequent v2 addendum verified the fresh-scratch working directory, compiler/profile pins, final executable use, four replay bindings, and corrected module metadata. It notes that final compiler/linker return codes were not serialized and that the exact 27 seed-copy bytes at compiler consumption are not independently proven. Review text is retained in the evidence bundle. This report remains uncommitted pending root integration.
