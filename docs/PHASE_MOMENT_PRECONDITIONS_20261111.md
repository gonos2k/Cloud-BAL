# 상변화 전에 필요한 모멘트의 유효성 검사

## 기준과 수정 범위

PR161의 마지막 코드 `8cae014febf057e0740461691bd1325d29af4373`과 병합 커밋 `359ef4be308fb44693fce87f601ae9b7fabe3835`는 동일한 Git 트리 `3c55e40c421e52df5f8825daaf5c41b6cb6f9e29`를 가리킨다. 병합만으로 새로운 계산이 추가되지는 않았다. 이번 변경은 `fix/phase-moment-preconditions`에서 다음 두 입력 검사를 추가한다.

| 명시적으로 수행할 연산 | 상변화 전에 필요한 조건 | 미충족 시 |
|---|---|---|
| 양의 구름수 완전 증발 | QC > 0이면 NC > 0 | 온도·여섯 수종·NC·NN을 모두 유지하고 실패 |
| 양의 싸락눈 융해 | 융해량 > 0이면 BG > 0 | 온도·여섯 수종·BG를 모두 유지하고 실패 |

유한성·비음수·공여량 검사와 기존 역방향 불일치(QC=0·NC>0, QG=0·BG>0) 거부는 유지한다. 새 수농도나 부피 하한을 만들지 않는다. 이 두 조건은 과정이 필요한 정보를 가지고 있는지 확인하는 최소 조건이며, PSD·밀도 허용범위 전체의 검증을 대신하지 않는다.

## 과정 이전에 검사해야 하는 이유

닫힌 완전 증발은

$$QC^+=0,\qquad NC^+=0,\qquad NN^+=NN^-+NC^-$$

를 사용한다. 미완성 입력 QC>0·NC=0을 먼저 증발시키면, 최종 상태의 QC=NC=0만으로는 원래 NC가 누락됐다는 사실을 찾기 어렵다. 싸락눈을 완전히 융해하는 경우에도 QG=BG=0으로 같은 정보 소실이 생길 수 있다. 따라서 **소모되는 모멘트는 상변화 전에 확인한다.** 정보가 부족한 호출자는 유효한 관측·배경·명시적 사전정보로 먼저 완성하거나 해당 과정을 수행하지 않아야 한다.

융해량이 0이면 QG>0·BG=0 상태를 변경하지 않는 무연산은 허용한다. 이는 상태가 완성됐다는 판정이 아니다. 이후 양의 융해에는 BG가 필요하고, 최종 모형 전달에는 기존 완성 검사가 그대로 필요하다.

## 검증

고정 Intel 프로파일의 새 scratch에서 상변화 보조 함수, 물·엔탈피 연산→공통 상태→모멘트 완성의 결합, 소스에서 추출한 rain slope 소비 분기를 O0/O2로 검증한다. 새 회귀 사례는 누락된 NC의 완전 증발, 누락된 BG의 부분·완전 융해와 무연산, 작은 양의 모멘트, 기존 비유한·음수·공여량 초과 거부를 확인한다. 거부된 호출의 모든 입력은 바뀌지 않아야 한다.

[검증 명령·소스 해시·로그](evidence/phase_preconditions_20261111/validation/receipt.json)와 [독립 검토](evidence/phase_preconditions_20261111/review/source_review.json)를 제공한다. 이전 PR161의 전체 회귀 실행은 기존 증거로 보존하며, 이번에는 수정한 함수와 직접 결합된 시험을 재실행한다. 전체 WRF 적분이나 영역 물·에너지 수지를 새로 검증한 것이 아니다.

Graphify 증분 갱신은 KLAPS50과 Cloud-BAL에 별도 날짜로 저장하며 기존 스냅샷과 wiki 이력을 보존한다. Fortran의 교차 파일 호출 추출은 부분적이므로 실제 호출 관계는 소스와 시험에서 확인한다. 구조 그래프의 갱신은 물리 또는 실행 검증이 아니다.

## 빙정 정책과 실제 첫 사용의 상태

기존 B1의 해석적 NI 허용구간 공집합 1,362개에 대한 물리 정책은 이번 두 검사로 해결되지 않는다. 질량·수종·입경 사전값·수농도 상한과 native 제한의 적용 시점을 바꾸지 않았다. 제약을 언제 적용할지, 수종 재분배를 어떤 정보로 정당화할지, 실제 모형의 순차 제한과 어떻게 연결할지에 대한 검증이 남아 있다.

이번 보조 함수의 호출자는 여전히 합성 시험이다. **운영 상변화 연결·실제 첫 이류·첫 KDM6 검증과 새 6시간 예보는 수행하지 않았으며 현재 B1을 유지한다.** 기존 보호 11개와 규준실험 회복 15개의 판정 기준도 유지한다.
