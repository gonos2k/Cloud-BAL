# PR84 first-consumption support and boundary contract

The current same13 initializer does not close first-consumption support. It writes every level only on mass-grid `[1:-1,1:-1]`, leaving a one-cell perimeter untouched. That perimeter contains positive QCLOUD, QICE, and QRAIN with zero paired QNCLOUD, QNICE, and QNRAIN. Scalar advection uses neighboring donors for the first updated interior cells, so valid interior moments alone are insufficient. The retained `wrfbdy` is a separate case: its water and KDM6 moment B and BT arrays are all zero at both native times, which is a valid empty forcing pair. It does not describe incoming cloud-bearing boundary observations.

## First 20-second window

The source-bound namelist is the genuine same13 configuration (`namelist.input` SHA-256 `59e949a1a9feffec06204f8abc9b090b3c294e1a501e9f9599cbfc10503646f6`). It selects a 20-second step, one domain (`e_we=235`, `e_sn=283`, `e_vert=40`), KDM6 (`mp_physics=37`), Shin-Hong PBL (`bl_pbl_physics=11`), scalar advection option 1, and specified lateral boundaries with `spec_bdy_width=5`, `spec_zone=1`, and `relax_zone=4`. The expanded namelist records fifth-order horizontal and third-order vertical scalar advection. Restart, cycling, nesting, and DFI are outside this cold-start window.

The selected PBL driver branch passes QVAPOR, QCLOUD, and QICE with their tendencies; it has no QN or QIB arguments on this configuration. The first KDM6 call consumes moist `qv,qc,qr,qi,qs,qg` and scalars `qnn,qnc,qni,qib,qnr`. The public scalar carriers are QNCCN, QNCLOUD, QNICE, QIB, and QNRAIN. Registry units are specific mixing ratios: QN fields are `# kg-1` and QIB is `m3 kg-1`. They are not volumetric concentrations in `m-3`.

The first-step support condition is therefore broader than the PBL call: every KDM6 mass/moment pair must be representable on the mass-grid cells consumed by the first microphysics call, and every donor cell reached by the selected scalar advection stencil must carry supported state. In particular, the order-five horizontal flux path and its near-edge fallback still read the outer mass-grid ring as donors for interior updates. `rk_update_scalar` limits the specified-boundary update region using `spec_zone=1`; this does not remove the perimeter from upstream donor reads. The PR83 v1 initializer’s excluded perimeter is consequently live support, not a safe untouched margin.

The minimum current closure is a source-policy-supported initial Q/N/B state over the complete mass grid, including the existing one-cell outer donor ring, followed by the same preserved actual 13:00 B and 13→14 BT forcing. Current `wrfbdy` B and BT values are zero for every inspected water/moment field at both times, so they are internally paired empty forcing. They should remain described as the legacy zero-cloud boundary forcing; there is no evidence here that the boundary represents observed cloud. The `wrfbdy` contains Time records 13:00 and 14:00, `bdy_width=5`, X arrays shaped `(2,5,39,282)`, and Y arrays shaped `(2,5,39,234)`. The first 20-second forecast window uses the 13:00 state and its stored tendency toward the genuine 14:00 record. Do not infer 14:00 moments by retiming 13:00 density or zeroing tendencies.

The source boundary contract has 80 required arrays for the five KDM6 water mass fields (QCLOUD, QICE, QRAIN, QSNOW, QGRAUP), five KDM6 scalar fields (QNCCN, QNCLOUD, QNICE, QNRAIN, QIB), and eight B/BT edge suffixes. Of these, 72 arrays are the five water fields plus the four water-paired moments; QNCCN is an unpaired scalar carrier with its own eight arrays. QSNOW has no KDM6 number companion. The read-only checker validates carrier presence, native times/widths/shapes/units, masks, fill values, and finiteness. For state B pairs it rejects negative mass or moment, positive mass with zero moment, and orphan positive moment at zero mass. BT tendencies may be negative and are checked for finiteness/missing values without requiring mass and moment tendencies to match. Run support is stricter than structural validity: the retained empty state is accepted only when all 80 arrays are exactly zero and the `wrfbdy_d01` SHA-256 equals `885591e6008e219d0b0f8a5a9c6cc3b48eae097d951d1ed731234108706b25d7`. Any populated boundary pair requires separate source-bound review; this checker does not claim generic PSD validity.

## Same-policy OFF/CPLD path and present blockers

If and when one complete prior can be formed, use the existing `initialize_same13_copy` transaction and the common receipt-aware same13 runner for each arm. Bind each receipt to that arm’s genuine input path/hash and the exact same policy ID/hash; do not create a second moment formula or policy implementation. The current OFF wrapper (`tests/run_pr83_same13_off_native_initialization.py`) deliberately passes `allow_prior=False`, so it is a no-prior control and currently rejects a candidate prior. Retain that control. A future initialized-OFF arm needs the common receipt-validated path enabled as its own explicit arm. The current initializer only copies/updates `wrfinput`; it has no wrfbdy transaction. The existing PR83 v1 receipt cannot be reused: it is globally blocked, names a different source input hash, has no output path, and commits zero cells. It records the earlier policy-domain result only; it does not establish a persistent native KDM6 cap or the status of the separate v2 policy work.

The earlier PR83 v1 policy transaction found 2,305 QNICE positive-mass cells where that policy’s declared source-PSD lower bound required at least `1,095,670.9 m-3`, exceeding its selected `1,000,000 m-3` internal-number cap. Its receipt status is `BLOCKED_SOURCE_CAP_INFEASIBLE`; that finding is a rejection of the v1 prior-domain intersection, not a persistent native KDM6 upper invariant. The v2 source-compatible guard and its full-domain prior are separate work and were not executed by this support review. The smallest support scope remains single-domain same13 cold start and the first 20-second forecast interval.
