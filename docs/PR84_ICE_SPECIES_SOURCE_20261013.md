# PR84 ice species source trace

## Finding

The LAPS `ICE` input is a cloud-ice content field produced separately from rain, snow, and precipitating ice. The source code calls the Smith–Feddes liquid/ice routine, keeps its `cice` result distinct from `slwc`, and writes `ICE` as `Cloud Ice Content - LAPS Smith Feddes`. LAPS LAPSPREP then labels its WPS `QI` field `QICE` and `Cloud ice mixing ratio`; it writes the other precipitation reservoirs independently as `QR`/rain, `QS`/snow, and `QG`/graupel. This supports mapping the cloud-ice mass reservoir to WRF `QICE` for a mass-category policy. It does not support treating `QICE` as all solid hydrometeors, assigning particle habit/size, constructing `QNICE`, or moving QICE mass into snow or graupel.

The source reports cloud ice mass content, not a direct observation of pristine crystals. In the Smith–Feddes implementation, ice fraction is a modeled phase component: the documented dilution varies linearly from all liquid at −10 °C to all ice at −30 °C. Thin-cloud insertion also assigns all ice at/below 243.15 K, all liquid at/above 263.15 K, and splits between them in the interval. These are model allocation rules, not a measurement of crystal habit.

## Producer and actual archived product

`klaps-v5.0_/src/deriv/laps_deriv_sub.f` calls `get_cloud_deriv` with `iflag_slwc=13` and separate `slwc,cice` outputs (lines 558–581). `get_cloud_deriv.f` identifies 13 as New Smith–Feddes LWC and calls `get_sfm_1d` to return both liquid and ice arrays (lines 60–78, 482–535). The upstream routine documents the Smith–Feddes method and its liquid-to-ice temperature dilution ( `src/lib/smf_wisp92.f`, lines 39–53). LAPS then inserts thin cloud using temperature-dependent liquid/ice assignment (`src/deriv/cloud_deriv_subs.f`, lines 184–204), converts `slwc,cice` from g/m³ to kg/m³, and emits six separate named fields: `LWC`, `ICE`, `PCN`, `RAI`, `SNO`, `PIC` (`src/deriv/laps_deriv_sub.f`, lines 925–974). The comments call `ICE` cloud ice content and `PIC` precipitating ice content (lines 956–961).

The PR81 retained input inventory names the actual analysis-valid 13 UTC products and binds their hashes. Its `.lwc` input is `.../prepared/lapsprd/lwc/262281300.lwc`, SHA-256 `9e70f80275cb2cf48b3db9dd189fba04936d6587fa57bf15692100548b242cca`; this matches the hash in `/var/tmp/pr81_joint_thermo.HbL5ry/inputs.json.archive`. The file is a LAPS NUWG NetCDF product titled `LAPS lwc file - cloud liquid, ice and hydrometeor concentration`, with one record and dimensions `z=22, y=283, x=235`. Actual variable attributes say `ice`: `long_name=cloud ice`, `units=kg/meter**3`, `LAPS_var=ICE`, `LAPS_units=KG/M**3`; its stored comment is `Cloud Ice Content - LAPS Smith Feddes`. In the same file, `sno` is `snow content`, `rai` is `rain content`, and `pic` is `precipitating ice content`, each with kg/m³ units and distinct comments. The actual record valid and reference times are both epoch `1786885200` (2026-08-16 13:00 UTC).

In that actual `.lwc` file, raw `ice` is positive in 104,392 of 1,461,010 3-D cells, with maximum 0.003383725 kg/m³. Separate `sno` is positive in 70,486 cells, `rai` in 93,088, and `pic` in 245 cells (PIC maximum 0.004294541 kg/m³). These are source-product content values; they are not kg/kg mixing ratios. The values show nonzero independent reservoirs in the actual input and give no basis to fold them together.

The corresponding `.lsx` is the LAPS surface product, not the hydrometeor product: it has one vertical level and contains surface `t`, `p`, `rh`, `mr`, winds and diagnostics, with no `ice`, `sno`, `rai`, or `pic` variables. Its SHA-256 `482bd19494fde9625097a580fae3702752c2899776338a74b8d406e1e9a8125d` also matches the archived PR81 inventory. In the canonical reader, `.lsx` supplies surface temperature; the `.lwc` file supplies the five separate hydrometeor fields.

## Source-to-canonical and source-to-WPS mapping

`read_real_shadow_state` in `src/common/cloud_bal_real_netcdf.f90` opens the `.lwc` file and reads `lwc→cloud_water`, `ice→cloud_ice`, `rai→rain`, `sno→snow`, and `pic→graupel` as separate fields (lines 499–512). `read_and_assign_hydrometeor` validates kg/m³ units and divides each content value by dry-air density computed from pressure, temperature, and vapor, yielding canonical kg/kg dry-air values; it also reverses the source vertical order into the pressure-grid state (lines 4021–4065). The LAPS species receive cloud-analysis plus output-adapter provenance. No code in this mapping reclassifies `ice` into `snow` or `graupel`.

The LAPSPREP WPS writer consumes those same distinct arrays (`src/lapsprep/module_lapsprep_wps.f90`, arguments and comments at lines 82–107). It writes `ice` under `QI` with units `kg kg{-1}` and description `Cloud ice mixing ratio` (lines 484–502); `sno` under `QS` as snow (lines 558–579); `pic` under `QG` as graupel (lines 591–614); and `rai` under `QR` as rain (lines 525–552). LAPSPREP first scales hydrometeor content by `2/dx` and divides by density. It also bounds scaled cloud ice to `autoconv_ice2sno=0.0005 kg/m³` before division (`src/lapsprep/lapsprep.f90`, lines 156–161 and 584–589; `src/lapsprep/module_constants.f90`, lines 46–51). That legacy bound does not transfer excess into `sno`: the code only assigns the bounded `ice` array and later writes `sno` from its own independent input array. This trace records the existing behavior; it does not endorse raising or otherwise changing the cap.

## Policy implication and limits

A physically supported **mass-category** mapping for policy v2 is `LAPS ICE content → canonical cloud_ice → WPS QI → WRF QICE`, while keeping `SNO/PIC` in the independent snow/graupel reservoirs. This follows the source semantics and field-by-field implementation, rather than the variable name alone. It identifies cloud-ice mass, not individual crystals or their size distribution.

The archived PR83 same-13 native initialization evidence reports 244,498 positive QICE cells, and the PR83 cap audit reports 2,305 active-interior cells outside its declared internal-number cap envelope. The separate PR82 observation fit has 162 horizontal analysis-support cells. The initialization readback establishes that hydromass fields pass through that initialization unchanged; broad source QICE can therefore be inherited beyond a limited observation-analysis footprint. The existing evidence does not establish the exact overlap between the 2,305 infeasible cells and the 162 support columns. It also does not validate an ice-number basis or an ice PSD for those cells. Keep the observed high QICE mass in its source category for diagnosis; do not create snow/graupel by subtraction or claim a complete native microphysics state from this mass-only mapping.
