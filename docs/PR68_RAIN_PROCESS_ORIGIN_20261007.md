# PR68 rain-process origin audit

## Finding

The selected PR67 research executable’s 25 first-call `QR>0, NR=0` cells all become zero-number cells at the cold-process update inside the same KDM6 call. They are not first created by rain-to-cloud reclassification, the final rain threshold, slope repair, or return finalization. The matched trace records all 25 as cold (`T=271.27512–273.12845 K`, `dtcld=20 s`) and contains 300 source-checkpoint records, including the call entry, both sedimentation stages, freezing transfer, cold limiter before and after scaling, cold update, later classification/threshold/repair, and terminal return.

At the cold number limiter ([selected source lines 2652–2662](/var/tmp/pr67_budget_capture_20261007/source/module_mp_kdm6_combined_research.f90:2652)), the active source sets `value=max(nrmin,nrs)` and computes the aggregate sink tendency from `-nraut+nraci+nrcol+niacr+nsacr+ngacr` times `dtcld`. If that tendency exceeds `value`, it scales the participating number rates. For all 25 targets, `value` is the pre-update `NR` (24.92388–3335.99097), not `nrmin=0.01`; the unscaled aggregate source exceeds the value (25.39462–9850.11035). The observer independently reconstructs this expression, the `max` reserve, the limiter factor, and the post-limit rain-number and rain-mass trials in binary32 arithmetic.

After rate scaling, the rain-number trial is `-0.000244140625` to exactly zero (12 negative and 13 zero). The source then applies `max(trial,0)` in the paired mass/number update ([lines 2686–2690](/var/tmp/pr67_budget_capture_20261007/source/module_mp_kdm6_combined_research.f90:2686)), leaving `NR=0`. The independently updated rain-mass trial remains positive in all 25 cells (`1.09e-8–8.34e-5 kg kg-1`), so the native update retains positive `QR`. Every later observed checkpoint preserves that pair through KDM6 return. This is a near-zero number cancellation at the accepted limiter boundary, with mass and number updated from separate process-rate combinations. The captured rates do not justify attributing the result to one sink such as rain self-collection alone.

Internal `qrs` is rain mixing ratio; the selected microphysics driver passes `NR=qnr_curr` and `DEN=rho` ([exact driver call excerpt](evidence/pr68_rain_origin_20261007/selected_driver_call.txt); retained source lines 2278–2292). The selected KDM6 wrapper copies `nr` directly into `nrs` and returns `nrs` directly to `nr` ([wrapper lines 354 and 392](/var/tmp/pr67_budget_capture_20261007/source/module_mp_kdm6_combined_research.f90:354)); no conversion appears in these inspected sources. KDM6’s internal formulas `nrs=den*qrs*lambda^dmr/pidnr` and `nraut=3.5e9*den*praut` imply a volumetric-number convention (`m^-3`, with tendencies `m^-3 s^-1`), while the host Registry labels `QNRAIN` as `kg^-1`. The source-formula inference does not establish matching semantics across the direct driver/wrapper boundary, nor does it establish a runtime unit bug. The host QNRAIN producer and `rho` adapter lineage remain open because the retained host object/source closure is partial.

## Scope and unresolved physics

This identifies how the captured source arithmetic creates the 25 zero-number states. It does not establish that the resulting positive-mass/zero-number state is physically admissible, quantify downstream forecast impact, or supply a conservative correction. No number floor, reflectivity substitution, or physical process patch was applied. In particular, a self-collection-only repair is rejected as unsupported by these traces: all cold branch sinks and separate mass tendencies remain visible, and the observed result is not uniquely attributable to `nrcol`.

Earlier observer drafts with reversed branch labels, stale insertion offsets, or failed compile placement are excluded from this finding. They remain in the external research directory for audit history; only the final4 source/run bound by the evidence bundle is used here.
