# Paired native-corner state snapshots

The frozen [protocol](protocol.json) binds the 24 existing NetCDF inputs, target mapping, source formulas and predeclared layer summaries. The inputs are three cases (`B1`, `NR_PRIOR`, `DM065`), each with the pre-start `input` file and seven separately labeled forecast histories `h00` through `h06`. No WRF forecast or candidate was generated for this extraction. Each history is an Eulerian grid snapshot, not a parcel trajectory or the first time an event developed.

`results/<case>_<time>.npz` contains the same 3,688 RN1 `flat_index_yx` keys in C-order `(y,x)` on the 253 × 149 target grid. The `native_j_zero_based`, `native_i_zero_based` and `corner_weights` arrays have shape `(3688,4)` and corner order `00,10,01,11`. The PR146 mapper uses a WRF crop; its native indices are offset by `+5` in j and `+74` in i. `model_level_1based` is `1..39`.

Point profiles have shape `(3688,39)`: `qrain_kgkg`, `qnrain_per_kg`, `qvapor_kgkg`, `temperature_K`, `pressure_Pa`, `rh_liquid`, `rh_ice_or_water`, `height_agl_m`, and `dm_mass_weighted_mm`. Humidity is a fraction, not percent; no supersaturation cap is applied. The temperature and humidity calculations use source-coupled formulas in float64 at each native corner, and stored profiles are float32; these diagnostics are not bit-identical KDM6 runtime values. The independently checked dry/moist theta discrepancy is the residual `(T+300) - (THM+300)/(1+(461.6/287)*QVAPOR)`, not raw `T-THM`. Exact source snippets and source hashes are in [source_context](source_context/manifest.json).

`corner_qrain_kgkg`, `corner_qnrain_per_kg`, `corner_rh_liquid`, `corner_dm_mass_weighted_mm`, and `corner_dm_valid` have shape `(3688,39,4)`. The unclamped gamma moment diagnostic is `Dm_mm = 5000 / cbrt(4000*pi*QNRAIN/QRAIN)` only when both fields are positive. It is not evidence that KDM6's internal number minimum or slope-limiter branches were active: output histories do not bind the exact internal density. An undefined diameter remains NaN. Point `dm_mass_weighted_mm` is NaN unless every positive-weight corner is valid; `dm_valid` and `dm_valid_weight` preserve coverage without renormalization. B1 input and `h00` have no valid Dm values because their QNRAIN is zero, not because the diameter is zero.

Predeclared layer fields use `layer_<band>_<quantity>_level_mean` for `<band>` `0to1km` and `1to3km` and `<quantity>` `rh_liquid` or `temperature_K`. The interval is `[0,1000)` or `[1000,3000)` metres AGL. At each native corner, the arithmetic mean over the model levels inside the interval is computed first, then the four means are weighted. These are model-level means, not thickness- or mass-weighted layer averages. A point mean is NaN when any positive-weight corner has no level in the interval. The corresponding `_valid`, `_valid_weight`, and `layer_<band>_corner_level_count` arrays make missing coverage explicit. No physical threshold here is a forecast admission gate.

The [initial input comparison](initial_input_comparison.json) checks all 207 non-QNRAIN variables and all attributes and dimensions across the three initial inputs. The [extraction receipt](results/receipt.json) pins source and output identities; the [independent review](independent_review.json) checks all 24 outputs and representative scalar calculations. Source files and forecast histories remain external; their exact SHA-256 and byte counts are recorded in the protocol. These profiles do not establish full water or energy closure or mass-weighted columns.
