# Candidate calculation and provenance limits

The [disassembly](candidate_disassembly.txt) and [receipt](receipt.json) bind this investigation to the executable SHA-256 `de110a7f1d40143a74ffedbe64ed5b3717c413876093f56d200563e2f6b9c168`. Addresses are specific to this binary. The earlier [full listing](../../cp02_source_write_20261029/binary/producer_candidates.txt) contains the alternate stores and the inputs to the expression.

For a selected element `r15`, the instruction at `0x25ef8ca` loads a single-precision array element at `*(rbx+0x1b8)+4*r15`. It subtracts the single-precision constant at `0x34b9028` (`0x25ef8d8`), converts the result to double (`0x25ef8dc`), and multiplies it by the double array element at `*(rbx+0xe8)+8*r15` (`0x25ef8e7`). The resulting `xmm2` is multiplied into `xmm4` at `0x25ef928`; `xmm4` is then divided by the double element at `*(rbx+0x160)+8*r15` (`0x25ef933`), converted to single (`0x25ef93c`), and multiplied by the single constant at `0x34b9028` (`0x25ef940`). The other factors of `xmm4`, including the square root and earlier array inputs, are in the listing; this sequence does not alone prove which input causes a zero at runtime.

At `0x25ef944`, `comiss` compares positive zero with the candidate. `jbe` at `0x25ef947` chooses `minss` and store `0x25ef2a8` for a finite candidate greater than or equal to zero, including either signed zero; finite negative candidates take two `maxss` operations and store `0x25ef98f`. An unordered comparison also takes `jbe`, so this description cannot be generalized to NaNs. SSE `minss` and `maxss` select their second operand on equal or unordered values; a mathematical min/max description alone omits that detail. Floating-point mode, underflow, and intermediates must be captured before attributing a zero.

The B input to the prior difference is `*(rbx+0xb0)+4*r15` at `0x25ef2e8`; A is `*(rbx+0x120)+4*r15` at `0x25ef2d6`. These formulas identify addresses, not physical names or the last writers. The prior capture's A address coincided with the observed Q address in its six selected cases.

The executable has no `.debug` sections. The co-located source, preprocessed file, and object are hashed in the receipt; its archive member is byte-identical to that object, and the KDM62D symbol has the same size in the object and executable. These facts are consistent with proximity but do not establish link provenance or prove the source used in the executable. The preserved compile logs predate this scratch build and a source input manifest binding this executable was not found in this bounded inspection. Consequently no source variable name, unit, physical intent, or model correction is inferred from the adjacent source.

The static alias alone cannot prove that this instruction is the last writer of any selected element; access-watch observations must establish that interval. The intermediate and constants have no verified physical identity.
