# Native QSNOW sensitivity runtime

This diagnostic experiment runs six native QSNOW scale factors in each of two fixed families. `CONTROL` uses the original WRF executable and actual original `wrfinput_d01` (displayed as **규준 실험**). `IMPROVED` uses the fixed WRF executable and producer background-preserved B1 input (displayed as **기존 개선안**). The six-hour namelist and boundary are identical across all 12 new cases. The two alpha=1 controls are reused from their separately sealed completed six-hour runs.

For each family and case, only `QSNOW` values change: convert source values to float64, multiply by float64 alpha, then cast back to native float32. Each candidate compares all 207 other variables value-by-value with NaN-aware equality and stored-value fingerprints, and compares dimensions, global attributes, and all 208 variable metadata. Changed-value counts, finite/nonnegative checks, extrema, means, and value hashes are in `qsnow_audit.json`; full metadata and source/candidate field hashes are recorded alongside the common plan.

The 12 new forecasts all completed successfully on the fresh executable Lustre scratch tree `/NHNHOME/WORKSPACE/26weather002_A/yhlee/KLAPS50/scratch/snow_sensitivity_20261030`. The sealed batch receipt records an elapsed wall time of 40m 27.7s (03:52:23.660–04:32:51.361 UTC), maximum eight concurrent cases, and 8 MPI ranks × 1 OpenMP thread per case. Eight disjoint CPU sets were allocated; slots 0–3 ran paired CONTROL then IMPROVED cases sequentially. `taskset` and Intel MPI pinning plus observed per-rank affinities are in each receipt. All cases exited 0 with `SUCCESS COMPLETE WRF`, all 89 staged regular copies and source inputs remained unchanged, and each case produced the exact seven hourly histories from 12Z through 18Z. `finalize_batch.py` validated all 84 histories, file hashes, embedded `Times`, finite/unmasked RAINC/RAINNC/RAINSH, and runtime invariants; see `final_receipt.json` and `history_validation.json`.

A separate initial attempt in `/tmp/snow-sensitivity-runtime-20261030` was preserved under `attempts/initial_noexec/`. It failed before WRF startup because `/tmp` is mounted `noexec`; it produced no histories and is not part of the successful batch receipt. The successful attempt used the fresh Lustre scratch tree above.

`selection_plan.json` is frozen before candidate forecasts. `common_plan.json` binds its SHA, source hashes, the 12 staged-input maps, QSNOW audits, family baselines, CPU slots, 89-file checks, and exact history interval/namelist/boundary pins. Per-case receipts under `cases/` bind the common plan and record command, timing, exit, success marker, rank affinity observations, post-run source/staged checks, and all seven output SHA-256 values. The original historical inventory retains its `DURING_RUN` timing label; the current source bytes were independently hashed before these new cases.

The intervention directly changes initial snow water without balancing other species or diagnosing surface snowfall. The runs are diagnostic sensitivity experiments and do not claim initialization balance, conservation, forecast skill, or operational suitability.
