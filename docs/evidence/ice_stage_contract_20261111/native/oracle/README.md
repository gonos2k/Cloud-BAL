# Streaming source-extracted stage oracle

`build.sh` creates O0 and O2 executables in fresh scratch using the pinned Intel profile; it prints their directory and hashes. Its generator checks the hash of `boundary/boundary.f90`, which is generated from the SHA-pinned CONTROL source and retains the source ice operators and REAL32 gamma/coefficient initialization. The extra program only reads input, invokes these operators, and prints results. `receipt.json` binds the generated source, executables, comparison data and scripts to hashes; executable paths refer to the recorded scratch build. Rebuild with `build.sh` if the scratch files have expired.

Source `tests/intel_toolchain.sh` before running an executable so the pinned Intel runtime is on the library path. Provide one whitespace-separated input record per line: `MODE density QI NI_volume QMIN NCMIN`, with MODE one of `SLOPE`, `PSD1`, `PSD2`, `PSD3`. Values are read as REAL32. Each output line is `MODE NI_HEX AUX_HEX ACTIVE`: the two uppercase eight-digit hex words are the REAL32 bit patterns of final NI and the auxiliary value. For SLOPE, auxiliary is inverse lambda and ACTIVE is one when QI > QMIN. For PSD, auxiliary is the selected lambda if the source gate is active, otherwise -1.0; ACTIVE is the actual source gate. Input NI is already per volume: this oracle does not apply the wrapper or entry clamp.

`check.py` compares each captured full-routine input with the corresponding observed output, using bit patterns for NI and inverse lambda or selected lambda. It passes all 2,340 rows at each optimization (585 per operator) with no mismatches. Saved input and output streams and `check_O*.json` make that comparison inspectable. This verifies the extracted stage operators for these captured states; it does not independently validate other full-routine physics or the provenance of model input fields.
