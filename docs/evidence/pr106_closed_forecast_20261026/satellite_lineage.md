## Source trace

- `klaps-v5.0_/src/ingest/satellite/lvd_gk2a/lvd_driver_sub.f:442-452`: branch for `csatid='kogk2a'`, `csattype='ami'` calls `read_gk2a_ami`.
- `read_gk2a_ami.f:71-84,104-113,197-205`: channel descriptor `chtype(k)` maps through `lvd_file_specifier`; the reader opens `<PATH_TO_RAW_SAT>/<systime-derived YYYYJJJHH>_<chtype>`, NetCDF var `image_pixel_values`. For spec 4 (11 µm route), it reads int16 values, masks low 13 bits (`IAND(...,8191)`), extracts QC from upper bits, then loads IR window. `lvd_file_specifier.f:26-32` maps `i11` or `11u` (also `ir`) to internal slot 4. The code does not name the GK2A spectral channel number here.
- `lvd_driver_sub.f:676-715`: non-ASCII input counts are transformed in-place with `btemp_convert_ami` using `ir_cnt_to_btemp_lut` for spec 4. `btempconvert_ami.f:14-23` does `image = lut(int(image))`, preserving the configured missing-data sentinel.
- `lvd_driver_sub.f:821-859`: spec 4 image enters `process_ir_satellite`; successful result writes `ta8` to `S8A` with descriptor `kogk2a (11.2u) IR B-TEMPS - AVERAGED`; companion outputs are `S8W` (warmest) and `S8C` (extremum/filtered).
- `satir_process.f:98-112,140-148` sets valid BT range for `i11/11u` and invokes `satdat2laps_ir`.
- `satir2laps.f:64-71,85-123,124-173`: for `r_grid_ratio < 0.5`, input pixel footprint is centered on LUT ri/rj with half-width `0.5/r_grid_ratio` in each axis; integer starts/ends delimit a rectangular window. Missing input pixels are skipped. For >1 valid pixel `S8A`(ta) is arithmetic mean, `S8C` chooses warmest or coldest by majority relative to midrange, `S8W` is warmest. With one valid pixel all three equal it. If grid ratio >=0.5, code takes spline path (`satir2laps.f:235-249`), so actual footprint branch for this data would require the runtime LUT/grid-ratio input; no measured numeric ratio/window for this LVD was established.

## Numeric fixed-support replay (bounded, read-only)

A Python translation of the Fortran operations was evaluated on the source grid for filtering, and compared only at the nine frozen original QC LAPS cells `(j,i)=(16..18,134..136)`. It read the exact 14Z IR112 archive file, the DABA crop settings, the actual binary navigation LUT, and `ANAL/NE57/DABA/lvd/kogk2alookup/11u.lut` (the path resolved by `read_gvarimg_cnt2btemp_lut.f` after the wrapper symlinks `DABA/lvd` to runroot `static/lvd`). QC words were decoded using the source's low-13-bit count and upper-two-bit QC masks; rows were flipped and crop indices applied as `read_gk2a_ami.f`/`load_image_ami` do. The saved namelist implies ratio 0.4 from 2 km IR resolution and 5 km grid spacing; this is explicitly a config inference, not a historical runtime receipt. The two source Shapiro filter passes were applied only where the source passes the first output argument through `ta8` to S8A.

At all nine cells, replayed, filtered window maxima equal actual LVD S8A exactly (0.000 K difference). Actual LVD S8W equals the unfiltered arithmetic BT window mean exactly at those cells. Window bounds are 1-based on the cropped input array; the exact LUT ri/rj and bounds, valid pixel count, and actual/replayed values are preserved in the final `satellite_support_replay.json`. The exclusive-create command was `python3 /var/tmp/pr106_satellite_lineage_20261026/replay_support.py --output /var/tmp/pr106_satellite_lineage_20261026/replay_support_result_v3.json`. Input and source hashes are captured before and after and unchanged. The output preserves per-cell ri/rj coordinates, 1-based source pixel bounds, valid pixel counts, float32 byte equality, and S8W mean differences. This is strong numeric support for the channel lineage and actual aggregation semantics, but does not prove the exact raw/calibration/nav files were staged by that historical run; no producer receipt was found.

This replay exposed an implementation/comment mismatch: `satir_process.f:140-148` calls `satdat2laps_ir(...,tb8,tc8,ta8,...)`; `satir2laps.f:11-15,124-173` maps its first output `sa` to mean and third `st` to warmest; `lvd_driver_sub.f:848-859` writes `ta8` as S8A and `tb8` as S8W. Numeric replay confirms source-as-written semantics: S8A = filtered warmest window value; S8W = unfiltered mean. This contradicts comments/descriptors in source and PR105's description of S8A/S8W. Do not describe S8A as averaged without noting this discrepancy.
