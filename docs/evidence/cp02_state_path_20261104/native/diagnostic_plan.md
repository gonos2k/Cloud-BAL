## Capture stages

All global snapshots are limited to `itimestep == 1`, inside the existing 0–360 timestep trace gate. The WRF history grid is 234×282×39, but the physics call may exclude outer model bounds (prior runtime evidence included `its=2..233`, `jts=2..281`). Do not assume every history cell reaches KDM6. For each stage, retain exact float32 bytes and separate rank/tile ownership metadata for the actual union of runtime KDM6 core tiles, clipped to global history interior. Record every invocation's actual `its/ite/jts/jte/kts/kte` and corresponding memory bounds; exclude halo values. Represent global cells not reached by any invocation as `UNCALLED`; require OLD/FIX to have identical observed-call masks. Reject duplicate owners or missing cells inside the observed-call mask before comparing arms. Compare snapshots by global key; MPI rank, tile, call, or wall order is not a global causal ordering.

`PRE_UPDATE`, `POST_PROCESS`, and `KDM62D_RETURN` records are column blocks keyed to `j` and their local call. KDM6 physics is applied cellwise; cross-rank chronology will not be inferred from block write order.

The eight selected RN1 locations use all 32 mapped WRF corners, keyed by the pinned `native_instrumentation_coordinates.json`. Existing exact process/event phases and signed rates remain for timesteps 1–360. In addition, `SELECTED_ENTRY` and `SELECTED_RETURN` write the same 14 public fields at those 32 cells and all 39 levels for each timestep 1–360. Public `TH` is potential temperature in K; `T_K_DERIVED = TH × PII` is separately identified actual temperature. Public Q fields are retained as KDM6 mass-mixing-ratio values (kg kg⁻¹ convention) without inferring a separate host denominator; public N fields remain raw host number values and are not assigned a unit. Sparse rows carry explicit `(i,j,k)` keys and a block count. This gives a per-cell ledger: `D_return(t) = D_entry(t) + [(X_FIX_return(t) - X_FIX_entry(t)) - (X_OLD_return(t) - X_OLD_entry(t))]`, with `D = X_FIX - X_OLD`; then `D_entry(t+1) = D_return(t) + D_between(t)`. `D_between` is the net change between KDM6 calls from every non-KDM6 operation and is not labeled as pure transport. This separates incoming-state divergence from the change accumulated inside the KDM6 call without mixing `TH` with actual temperature `T_K`. Selected history complements, and does not replace, the first-step global snapshots.

## Binary output contract

Write versioned unformatted stream float32 state data, with no formatted full-grid dump. OLD and FIX run in distinct fresh working directories under `.../runtime/OLD` and `.../runtime/FIX`; filenames omit the arm because the case directory binds it. Before launch, require both case directories to be empty of `state_*.bin`, `state_calls_*.txt`, and `kdm6_trace_rank*.bits`. Reject stale files; never append onto a prior run.

Use deterministic field order from `state_schema.json` and separate files by arm/stage/rank. Each block has a header with version, stage, rank, call ID, timestep, actual tile bounds, unit strides, field count, and record count. Full-grid rows are packed in `j,k,i` order; each row writes exactly `field_count` REAL32 values (15 for private checkpoints, 14 for public checkpoints). Sparse selected public rows carry explicit integer `(i,j,k)` keys followed by exactly 14 REAL32 values. Include rank headers even when a rank owns no selected cohort cell; publish the derived occupancy mask and owner map alongside the blocks. In addition, `state_calls_rank<rank>.txt` records one row per KDM6 invocation for timesteps 1–360 with `itimestep,rank,call_id,ids,ide,jds,jde,kds,kde,ims,ime,jms,jme,kms,kme,its,ite,jts,jte,kts,kte`. This call manifest is the expected-block inventory: one ENTRY, WRAPPER_RETURN, SELECTED_ENTRY, and SELECTED_RETURN block per call; one PRE_UPDATE, POST_PROCESS, and KDM62D_RETURN block per `j` actually visited by each step-1 call. Reject any missing or extra block, duplicate owner, missing expected cell, halo cell, differing OLD/FIX invocation inventory, or differing observed-call mask. Cells outside that mask remain `UNCALLED`, not zero-filled. Compare public fields with public fields and internal fields with internal fields; never mix fields with different units.

The pinned parent Intel command supplies `-real-size 32`, `-i4`, and `-convert big_endian`; the patch writes 4-byte REAL and INTEGER values as big-endian unformatted streams. The runtime receipt must bind those exact options. At the full 234×282×39 upper bound, each arm carries `2×14 + 3×15 = 73` float32 values per cell, or 751,849,776 bytes; the pair carries 1,503,699,552 bytes (1.40 GiB) before block headers. The two selected public state stages have an exact upper-bound value payload of 100,638,720 bytes for both arms; explicit cell keys add 21,565,440 bytes, for 122,204,160 bytes total before headers. The retained parent selected text traces are 484,154,377 bytes OLD and 488,254,065 bytes FIX for the prior 16 corners. Doubling for 32 corners projects 1,944,816,884 bytes of selected text; adding the selected binary state projects 2,067,021,044 bytes (1.93 GiB) before headers. Use a 1.75 GiB global-snapshot cap, a separate 2.75 GiB selected-output cap, and a 4.5 GiB total instrument-output cap. The launcher must stop a case if a cap is reached; exceeding the projection is a budget failure, not a reason to truncate a file or interpret partial output. Place files only under shared scratch sibling `.../b1_state_path_20261104/runtime`, not `/var/tmp`.

For each shared checkpoint and field, report: bitwise equal count, unequal count, first differing global key in deterministic `(model timestep, checkpoint, field, k,j,i)` sort order, first OLD/FIX bit patterns and float32 values, max absolute difference, max relative difference where defined, signed difference range, and field-wide finite/NaN/Inf counts. Preserve all cell pairs and bits for reproducibility; never promote a count of changed cells to an amplitude claim.
