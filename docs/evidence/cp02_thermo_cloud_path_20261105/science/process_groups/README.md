# Two-hour group comparison and state ledgers

In a clean checkout with the verified parts bundles present, first rename `science/process_groups/results` to a fresh `results.reference` in the same bundle, then run `python docs/evidence/cp02_thermo_cloud_path_20261105/science/recount_process_groups.py` and compare the regenerated CSV hashes to `results.reference/receipt.json`. The script reads only the paired-difference parts and the pinned point and RAINNC references, checks all part/member hashes through the existing loader, and refuses to replace an existing `results` directory. The original full-capture analyzer and receipt are unchanged.

`point_metrics.csv` contains 39 points in each one-hour window. For each named state or process metric, its value is the maximum absolute DM065-minus-B1 difference over sampled calls and 39 model levels at that point, with the signed value, step and level of that maximum and the first sampled nonzero step. Values can be very small. The signed `RAINNC_hour_signed_difference_mm` is instead the difference of independently verified hourly KDM6 precipitation increments; RAINC is separate. `group_quantiles.csv` gives the median and linear-interpolation quartiles of these per-point values for all 15 selected initial-NR-unchanged new false alarms and all 12 selected removed false alarms; it is descriptive, not causal. First hour covers steps 1–180 and second covers 181–360. A between-call value bridges return step n to entry step n+1 and belongs to the window of its destination step.

`anchor_ledger.csv` contains level-2 QV and TK ledgers at steps 180 and 360 for 17051, 20183, and their nearest selected removed-false-alarm geographical comparators 16454 and 20330. For each row, `return_minus_initial` equals `sum_within + sum_between` up to the reported float64 residual and conservative operation-count rounding bound. QV sums are per-call local mixing-ratio differences, not column mass or a water budget. Between-call changes include all intervening model activity and are not pure transport. The diagnostic uses fixed Eulerian points, not trajectories. Sedimentation and conditional surface processing occur before the main process-rate update in each step.
