## Findings

### F1 — pre-stage and mid-dispatch exits can report unrun stages as successful

- **Class / priority:** Static receipt-coherence issue, P2; not runtime reproduced.
- **Location:** initial stage defaults `src/common/cloud_bal_pipeline.f90:292-300`; preflight and authority exits `301-446`; column/geopotential/beta dispatch exits `465-575`, including downstream skipped stages.
- **Trigger:** Any call rejected before a producer runs, such as invalid mode (`301-303`), physical mass preflight failure (`313-321`), malformed or manufactured target/boundary authority (`326-357`), unresolved model target (`360-367`), invalid optional-argument combinations or ranges (`403-446`); a beta-construction failure after column/geopotential processing (`564-575`) is a mid-dispatch example.
- **Observed behavior from source:** `column`, `geopotential`, and `balance` are initialized as `STATUS_OK` at `292-300`. Most preflight exits set the top-level result and `overall`, but leave producer stages at those initial successes. The authority/source guards at `326-357` also omit reinitializing `overall`: a wrong-shaped allocated `omega_target` or `omega_target_sigma` sets top-level `FAILED/REASON_SHAPE` while `overall` stays `FAILED/REASON_AUTHORITY`. The same skipped-stage issue occurs after a producer fails: column failure at `465-472` leaves balance `STATUS_OK`, and geopotential failure at `552-559` also leaves balance `STATUS_OK`. At `564-575`, `build_compact_balance_beta` failure occurs before `apply_localized_balance`, yet balance remains `STATUS_OK`; changed masks are cleared and only `overall` is reset to failed/range. Runtime exits after a stage has actually run generally copy that stage into `overall` or preserve successful stage-local receipts; the mismatch is specifically that downstream stages never entered still carry the initialized success state.
- **Consequence:** stage consumers can read a successful receipt for work that did not run; on malformed target shapes they can also read a different reason from `overall` than from the top-level result. Candidate/operational outputs are initialized from input and the inspected rejection paths preserve rollback, so this is a receipt issue rather than evidence of mutated output.
- **Existing evidence:** `tests/test_real_shadow_io_contract.f90:327-341` exercises manufactured-source rejection at a downstream writer boundary, not pipeline producer receipts. `tests/test_real_shadow_io_contract.f90:467-474` checks the estimator blocked-receipt path, whose branch explicitly marks stages failed. No existing assertion was found covering the pre-stage/beta failure receipts as a group.
- **Next reproducible check:** using the pinned Intel profile in a fresh scratch directory, run a focused fixture for malformed target shape and another for beta construction failure; assert top-level, overall, each producer status/reason, and exact candidate/operational rollback. No fixture or test was run in this read-only audit.

### F2 — estimator inlet evaluates a supplied endpoint; it does not produce or independently validate the estimator

- **Class / priority:** Explicit capability boundary / missing implementation if an in-repository estimator is required; scientific evidence gap, P1 for any claim of a usable estimator product (no defect if the intended scope is only endpoint accounting).
- **Location:** API and contract comments at `src/common/cloud_bal_pipeline.f90:40-70, 265-272`; endpoint gate at `686-771`; unassessed evaluation flags at `82-107`.
- **Concrete trigger:** no external caller supplies `estimator_candidate`.
- **Observed behavior:** the pipeline accepts an externally prepared `cloud_bal_state_type`, checks canonical metadata and contract accounting, records the endpoint, and intentionally returns `STATUS_FAILED/REASON_AUTHORITY` with operational output equal to background. The input is explicitly documented as an external estimator endpoint, not a pipeline-generated analysis. No `src/` call site passes `estimator_candidate`; source-level calls are limited to the implementation's internal evaluation flag and the real-shadow contract test. The evaluation type also states `observation_fit_assessed` and `optimality_assessed` default false, and the estimator path does not set them.
- **Consequence:** the code proves only the declared local component-feasibility/accounting gate for a provided endpoint. It does not demonstrate that an estimator can generate the endpoint, fit observations, be optimal, conserve against independent native sources/boundaries, or acquire publication authority. The interface is deliberately blocked SHADOW diagnostics, not an end-to-end estimator implementation.
- **Existing evidence:** `tests/test_real_shadow_io_contract.f90:463-474, 623-629` supplies a fixture endpoint, asserts blocked pipeline authority, then tests writer publication. Contract declarations at `cloud_bal_pipeline.f90:54-59` expressly leave analysis authority, source/boundary attribution, and native conservation unassessed. PR77 evidence artifacts are outside this team's runtime/scientific validation scope.
- **Next reproducible check:** if production estimator behavior is required, identify/build the estimator producer and wire its immutable endpoint through this API; validate observation fit/optimality and independent source/boundary/native conservation with independent evidence. Otherwise keep the documented endpoint-only scope and label artifacts accordingly. No estimator claim is inferred from endpoint replay.

Pressure-analysis wrapper defaults to failure and only upgrades its returned status when the pipeline succeeds and operational state equals input (`pressure_analysis.f90:44-50, 125-126`). This is static inspection; no runtime reproduction was performed.
