# Native CP05 sedimentation audit

This is an audit of the archived OLD/FIX native captures, not a new model run or a causal attribution of forecast differences. Phases 9/10 cover steps 1–360 and 721–900 only. The raw replay uses the recorded post-step `falk` and source-order float32 operations to reproduce each qrs and rain-number POST bitwise. It does not infer unrecorded fall velocities or audit the separate cloud-ice loop. The upper state in the incoming `min` is the already updated POST state. Rain, snow, and graupel use `dend * delz` as captured; rain number uses `delz` alone. `brs` is excluded because its physical volume units have not been established here.

`p01_focused_proof.json` gives the 31-call 330–360 window and the aligned 30-call 331–360 window separately, with the four-corner native sum and the P01 (`RN1_10942`) bilinear result. Its `inputs_sha256` verifies every P01 raw process chunk and call inventory used. No area integral is implied by adding four native columns. The ground boundary is the recorded `fall` increment multiplied by thickness and `dtcld`; it is not asserted to equal RAINNC. Event tables identify each limited interface; substep tables include every audited column/substep and species. The focused tables have columns in the same order as the full table header defined in `tools/cp02_sedimentation_conservation.py`, but omit that header. Their rounding residual was computed using nominal flux as the lower boundary; for the definitive full audit the code instead uses the actual limited bottom removal, keeping the difference from nominal ground flux separate.

`raw_subset` contains exact full source-frame bytes for step 330 at j=79,80, including other selected columns in those frames. The accompanying receipts record the verified original file SHA-256 and byte ranges. The portable subset does not itself establish full-window coverage. `tests/test_cp02_sedimentation_raw_audit.py` replays all four P01 corners from these files and checks the manufactured two-layer case, invalid data and a one-bit mutation.

The full streaming audit checks all recorded input file sizes and SHA-256 values against the prior capture receipt, call-inventory ownership, exact expected frame keys, 39 levels, paired 1..mstep coverage, finite inputs, POST bits, fall accumulation, and the column arithmetic residual. It uses tolerance `32 * epsilon(float32) * scale + 1e-30`, where scale is the sum of absolute pre/post layer inventories, bottom removal, and interface gaps. Interface gaps retain float32 rounding at unrestricted interfaces; limiter counts separately identify actual `incoming_raw > upper_post` events. Role native totals deduplicate columns within each role; point totals use frozen corner weights, and role point sums count each point once within a role. Roles can overlap and must not be added together.

To rerun the full audit from the repository root, set `OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1` and invoke `python tools/cp02_sedimentation_conservation.py --case CASE --arm OLD_OR_FIX --launch FULL_RUN_RECEIPT --output OUTPUT_DIRECTORY` once per arm. Input files remain external. `reproduce_p01.py` and `summarize_p01.py` document the focused run used for the frozen early proof and expect the original workspace layout; the small subset can independently exercise the step-330 arithmetic through the test above.

Full-run provenance limitation: `reconstructed_full_launch_source.py` is a post-launch reconstruction (SHA-256 `c5f0668357ce9d029ee9ec7e6ca8cefc9dfc9c5e6356ab3ba85f7e4ea3cfc931`), not a contemporaneous capture of the running process's source bytes. It restores the code before later capture-receipt pinning, role aggregation and transactional publication. The running jobs write only under scratch runtime; promote their results only after successful completion. The current tool writes to a fresh temporary arm directory and publishes `OUTPUT_DIRECTORY/ARM` only after successful coverage and arithmetic checks and role aggregation. Existing arm output is rejected rather than overwritten.
The role table also reports actual bottom-layer removal reconstructed from `rounding_residual - column_change - transfer_gap` and the difference between the fall-increment ground boundary and this removal. This keeps boundary accumulation rounding or a bottom outflow cap distinct from column storage rounding.

A subsequent final rerun uses the exact copied `executed_full_tool.py` and the capture-parser hash recorded in `full_launch_hashes.txt` before either arm was spawned. Its two result directories are distinct from the reconstructed-source first-pass attempt. First-pass outputs are retained in scratch only; their numbers should be compared with the final rerun before using the final tables.

The first exact-source rerun (`executed_full_tool_attempt_v1.py`) was stopped during processing after a real-cohort role-aggregation integration check exposed the `role_rows`/`point_roles` mismatch; it produced no published full result. The corrected v2 source is `executed_full_tool.py`, pinned before launch in `full_launch_hashes.txt`. A portable integration test now exercises raw frames, actual schema and cohort, role keys, CSV reduction and atomic publication; it uses a synthetic owner array for the subset. The stopped attempt's staging files remain external scratch, and no exit code is inferred for it.

The v2 rerun completed for both arms. `full/receipt.json` records exact decompressed equality of its substep and event tables and equality of summaries to the first pass, and independently verifies both P01 windows against the focused proof. `role_agreement.json` records byte-identical role tables from an independent aggregation of the first-pass tables. The maintained tool and executed v2 copy have the same pre-launch SHA-256. For a reproducible final publication, run `python docs/evidence/cp02_sedimentation_conservation_20261109/audit/finalize.py --final-run FINAL_RUN --first-pass FIRST_PASS`; it rejects incomplete runs, mismatches, and an existing destination.
