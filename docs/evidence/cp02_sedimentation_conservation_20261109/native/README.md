# Native sedimentation kernel evidence

`source/module_mp_kdm6_FIX_baseline.f90` is the unchanged standard B1 FIX source (SHA-256 `0b468be19f7dd66ad2f6e65a53b42f10391a4565831a96c80dddddf21934cf79`). `source/module_mp_kdm6_FIX.f90` is the result of applying `patches/kdm6_conservative_sedimentation.patch` to that source. The patch does not alter the archived model source or other process calculations. The existing protected-process correction is retained.

For each substep, the patch computes one transfer for each donor boundary before changing any cell. The bound and exchange use the same area inventory: `dend*delz*q` for rain, snow, graupel, ice, and `brs`, and `delz*n` for rain and ice number. `work1` and `workn` retain their distinct velocities. Surface `fall` and `falln` use the limited transfer divided by `dtcld*delz`; the existing surface conversion is unchanged. Physical transfer and local update arithmetic use REAL64; model state and accumulated fall retain their original REAL32 types. This assumes finite nonnegative donor values, positive finite density, layer thickness, and timestep, and nonnegative velocities, as the source's existing sedimentation calculation does. It does not add input validation or rollback.

`run_intel.sh` applies the patch to a fresh copy and verifies identity against the candidate, extracts the actual update statements into the driver, and runs the candidate and baseline plus a floating-point counterexample with the pinned Intel profile at O0 and O2. Reproduce from the Cloud-BAL root with a fresh path outside the checkout:

```sh
bash docs/evidence/cp02_sedimentation_conservation_20261109/native/run_intel.sh /path/to/new/scratch-directory
```

The script sets `TMPDIR` to that directory. `intel_receipt.txt` records the run, including the expected baseline failure. For the literal review case (upper q=0.001, rho=1, dz=100, dt=20, velocity=3.75), baseline initial mass 0.10000000475 becomes 0.05000000820; the candidate returns upper q=0.00024999998 and lower q=0.00075000006. Other cases cover unequal density/depth, independent number velocity, zero and 1e-30 inventories, four substeps, and limited bottom outflow, for all seven quantities. The maximum relative residual across column plus bottom outflow was 3.214e-8, within the test's 1e-6 scale-relative tolerance; REAL32 state/fall stores preclude bitwise conservation. Fixed test velocities isolate the extracted kernel; the test does not exercise model velocity recomputation or a full model forecast.

`float32_cap.F90` confirms that a simple REAL32 flux cap can produce a negative donor even when the cap was computed from its full inventory. Both Intel optimization levels produce `q-dq = -2.7105054e-20`. This motivates limiting and applying transfers in REAL64 rather than silently clipping that residual. `incorrect_extraction_failure.txt` captures a reproduction of the initial harness compilation error when trace instrumentation was inadvertently extracted along with the transport statements; the final extraction stops before that instrumentation. The initial compiler invocation also used the compiler's default temporary directory; subsequent recorded validation sets `TMPDIR` explicitly.
