# Manufactured phase completion and native slope consumer

`tests/run_phase_moment_consumer.sh` passed checked (`-O0`) and optimized (`-O2`) profiles on 2026-11-11 using the pinned `tests/intel_toolchain.sh` IFX 2026.0.0 in a fresh temporary directory. It runs the real `apply_water_phase_transfer` through caller-side completion on manufactured states. Complete cloud evaporation moves the old cloud number to the pre-existing free CCN reservoir and sets cloud number to zero. This is one explicitly closed internal process on a fixed dry-air basis, not a universal conservation rule for NC+NN, and does not prescribe aerosol behavior for other processes. A rejected transfer leaves temperature, all species, and both moments unchanged.

For a prescribed graupel-to-rain mass transfer, the test checks the phase primitive and remaining BG fraction together. The selected native rule at CONTROL.f90:1727–1735 applies `brs += pgmlt/rhox`; when density is the unclamped ratio `rhox=qg/brs` this is exactly the proportional remaining-volume rule. The test uses QG/BG = 200 kg m-3, within the native 100–900 kg m-3 density range. The helper implements only that selected proportional rule; native density clamping, kinetics, and the separate native rain-number creation are outside this manufactured test. An excessive melt is rejected without changes. Water and BG are per unit dry air; the number reservoirs are per unit dry air. These results do not establish runtime coupling or a forecast impact.

The test extracts `slope_rain` verbatim from `docs/evidence/cp02_activation_path_20261110/native/source/CONTROL.f90`, after verifying SHA-256 `f391b211c6e111f92a7213cc5a651606ec6b5826a47063e3057ab2d819e9a595`. The harness supplies the native relevant slope constants and initialized `pidnr`; velocity coefficients are placeholders because velocity is not assessed. With single-precision q=1.1e-9 kg/kg, density=0.8 kg/m3, and intended Dm=1 mm (lambda=5000 m-1), the calculated volume number is 0.0087535214 m-3. Although q exceeds qcrmin, the native `nrs <= 0.01` branch returns the fallback lambda 35000 m-1. The test verifies number equality and the next representable value above the threshold, mass equality and its next representable value above, and that slope consumption does not increase number. This source-extracted manufactured consumer is not a full native model integration or a reason to force number upward.

The tested helper is not wired into a production phase caller. Additional process and aerosol closure choices, native storage rounding, and model integration require separate scientific validation. The actual B1 incompatibility remains unresolved; no first-use run or new forecast is justified without the physical decision. Prior historical evidence and the six-case code were not changed.

The phase-to-initialization chain additionally stores the manufactured post-transfer state in the canonical real32 fields and calls `complete_initialization_state`: the cloud number remains zero and the returned free-CCN number remains 100 kg-1; the returned BG is retained. For positive graupel melt into initially rain-free air, the helper does not update rain number. The test explicitly marks rain number missing and completes it using a declared, manufactured 1e-7 kg-per-particle prior; this is an example of completion policy, not native rain-number kinetics or a claim that the choice is physically calibrated. The chain checks the water sum and `moist_species_enthalpy` before and after each real64 transfer and verifies cooling; these checks precede the separate real32 state storage. Both zero cloud mass with positive cloud number and zero graupel mass with positive BG are rejected atomically. No universal conservation constraint on NC+NN is imposed.
