# XMM6 native capture plan

The pinned historical executable (SHA-256 `de110a7f1d40143a74ffedbe64ed5b3717c413876093f56d200563e2f6b9c168`) runs against a fresh copy of each original input set, under the pinned Intel profile. The `runtime/prepare.json` receipt identifies the scratch tree and binds all 88 source/copy pairs per arm. No Fortran was rebuilt. The helper retains the PR128 first outer-call, inner-call mapping, four hardware write watches and four preclamp breakpoints; all eight ranks settle before the intentional stop. The inherited context text describes the retained preclamp scope and does not list the additional producer breakpoints.

In each watched inner call, the early breakpoint callback explicitly checks `*(uint64_t *)(rbx + 0x18) + 4*r8 == target_qrs_address`. It does not rely on GDB evaluating the breakpoint condition, and does not assume `r12` is the qrs base at early PCs. The qrs address originates from the validated inner call and target tile offset. Each matching event records target, rank, PID, inner event ID, base/index, full frame bytes and registers, all sixteen XMM low-lane raw values, source base and cell bytes, frame operand at `rbx+0x140`, values, and backtrace. The existing preclamp callback separately guards `r12 + 4*r8`.

The producer breakpoints surround the load at `0x25f4492`, record comparison inputs at `0x25f44a4`, surround the conditional multiplication at `0x25f44be`, and record the join `0x25f44f7` and downstream `0x25f4a59`. The existing pre-sum breakpoint is `0x25f4e24`. A missing multiply event can indicate the branch bypass, and must be evaluated together with observed join, path and pre-sum events. The evidence establishes behavior for the six selected cells and first call only; it does not establish a process identity or forecast completion.

The stage wrapper freezes the helper under its inherited name `capture_preclamp.gdb`; its SHA-256 is bound by the context, raw records and receipt. The collector retains the earlier preclamp checks, verifies all ranks and input pairs, and archives raw captures and mapped runtime provenance. Further producer-specific validation is recorded separately.
