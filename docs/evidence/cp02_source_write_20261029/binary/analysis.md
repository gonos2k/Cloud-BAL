The resulting source row is saved as `[rbx+0xc0]` at `0x25f40a6`. Both the PR129 source and QR reads use `r8*4`. Consequently the earlier candidate source address is `[rbx+0x728] + (target_QR_address - [rbx+0x1f0])`, conditional on the target and frame belonging to the same invocation and on validating the relationship at the later load.

[Candidate producer listing](producer_candidates.txt): `0x25ef125–12c` places the allocation base in `[rbx+0x180]`; `0x25ef1bd` advances it by row stride. The stores `0x25ef2a8` and `0x25ef98f` each write `xmm0` to `[rax+r15*4]`, with `rax` loaded from that row pointer. These represent alternate paths: after `0x25ef944` compares zero to the candidate, `jbe 0x25ef290` selects `minss(candidate, [rbx+0x18]/constant)` and store `0x25ef2a8`; otherwise the path applies successive `maxss` bounds and stores at `0x25ef98f`. Both join at `0x25ef2bf`. The calculation at `0x25ef875–944` includes a square root, single- and double-precision operations, and indexed inputs; the listing alone does not establish which path a target takes or prove that these stores are its last writers.
