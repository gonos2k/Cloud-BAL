# PR98 native operator capture

## Observer and source locations

The observer is a source-mapped diagnostic overlay built from the receipt-bound C1 sources. It captures pre/post arrays around explicit U/V/W advection, horizontal pressure gradient, Coriolis, curvature, and horizontal momentum diffusion. Hooks are also present around vertical U/V diffusion, but that conditional source branch was inactive with `bl_pbl_physics=11`, so it emitted no snapshots. The observer saves the full `ru_tend`, `rv_tend`, and `rw_tend` arrays at the end of `rk_tendency` and immediately before and after the real `rk_addtend_dry` call. These endpoints include source updates that are not individually instrumented.

The arrays are stored on their native WRF grid: U on the x face, V on the y face, and W on the vertical face. `ru_tend`, `rv_tend`, and `rw_tend` are retained as raw coupled tendencies. No acceleration conversion or vertical weighting is claimed. The captured map factors and carrier arrays are available for source-consistent normalization; the overlay does not save every coefficient needed for all vertical W normalizations.

At the actual `advance_mu_t` call, the observer records mass `mu_2` before and after, `mu_tend`, the returned `mudf`, and the call's actual `dts_rk`. The separately inspected `module_small_step_em.F` source (`SHA256 cabf1a177d50fb0096db79644af20cfe6d75217dbe63ab406a7e29bb54c17634`) defines `MUDF = DMDT + MU_TEND` and advances `MU` using that sum, but this source is not proven to be the compiled implementation for the PR98 executable. Since the call-site observer cannot see local `DMDT` inside `advance_mu_t`, this capture supports reporting the returned combined mass source and observed mass change; it does not claim a separately closed flux divergence.

Each payload is a Fortran stream file with allocated and active bounds, written in the build's `-convert big_endian` format. Rank-3 payloads are Fortran `(i,k,j)`; rank-2 payloads are `(i,j)`, rank-1 are `k`, and scalars are rank 0. Rank-2/3 observer calls write once per tag and tile. The rank-1 `c1h` and `c2h` observer calls have no once guard and overwrite their files on each U-advection call, so those files hold the final repeated snapshot. In the pinned source, `c1h/c2h` are `INTENT(IN)` through `rk_step_prep` and `rk_tendency`, and `solve_em.F` passes the same grid arrays through the RK loop without assigning them; the three arms' final files are byte-identical. Inventory statistics describe full allocated arrays, including halos; they are not physical-region norms. Use [pr98_native_capture.py](../tools/pr98_native_capture.py) to inspect headers and compact raw-array summaries. The scientific comparison applies a common fixed support and native face-footprint mapping after reading the private payloads.

## Build and run provenance

The v4 overlay passed the pinned Intel `CLOUD_BAL_REPRO_FLAGS` build with the full receipt-bound C1 override set and its existing `pr90_cycle_support` observer. Build, compiler and source hash bindings are in [build_provenance.json](evidence/pr98_native_capture_20261022/build_provenance.json). Generated source copies and private raw arrays stay outside the tracked evidence directory.

The 20-second OFF, HYDRO, and COUPLED runs used the frozen PR96 runner, the C1 boundary and namelist settings, `OMP_NUM_THREADS=1`, and the exact current-generation HYDRO input receipt. All three receipts closed `COMPLETE`, return code 0, one timestep at model time `2026-08-16_13:00:20`, with no fatal lines. Wall times were 557.6 s (OFF), 546.5 s (HYDRO), and 556.1 s (COUPLED). All used candidate executable SHA256 `e919518165d52e26004858fa40293b7df806a9ba2a17af6ab320858f713768f1`; HYDRO input SHA256 is `46760bdf03e42cbc8e1f5b415e1b304b535d369689f95a421a287d1eb90b679c`. Receipt hashes and run bindings are in [run_status.json](evidence/pr98_native_capture_20261022/run_status.json). Each arm produced 57 private observer payloads (429,851,256 bytes); two-pass SHA stability and header/payload validation passed. Hash manifests and allocation-level inventories are in [evidence/pr98_native_capture_20261022](evidence/pr98_native_capture_20261022). The frozen-C1 runtime noninterference check passed bytewise: each arm's first-20-second 12-field record hash matches the C1 receipt, full-memory T1 `kdm6_first_call_pre/post` payloads (17 returned fields plus XLAND) match independent PR97 C1 expanded hashes, and 11 T0 history arrays (`U,V,W,T,PH,PHB,MU,MUB,P,PB,XLAND`) match at record 0. Details are in [frozen_c1_noninterference.json](evidence/pr98_native_capture_20261022/frozen_c1_noninterference.json). Scientific fixed-support comparison remains separate; these checks establish observer noninterference for the measured outputs, not scientific validity.

## Limits

The per-call snapshots are selected source contributions, not a complete decomposition. `pg_buoy_w`, `w_damp`, implicit advection, and any active sixth-order or Rayleigh terms are not individually captured. Use the end-of-`rk_tendency` and pre/post-assembly arrays for complete native tendency comparisons; do not sum the selected per-call increments as if they covered every mutation. The transform test confirms the original source tokens and operator calls remain unchanged after instrumentation. Successful diagnostic receipts and noninterference matches do not establish scientific validity.
